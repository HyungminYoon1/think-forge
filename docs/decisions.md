# 결정 기록

## D01 — 독립 정적 사이트

- 맥락: 네 프로젝트를 별도 GitHub Pages 저장소로 공개 요청.
- 대안: 하나의 사이트 / 별도 서버 기반 사이트 / 독립 정적 사이트.
- 결정: 독립 저장소, 브라우저 JS, 외부 런타임 의존성 없음, dist만 배포.
- 이유: 기존 Pages 운영 방식 유지, 개인정보·운영비 최소화.
- 영향: package.json, dist/, workflow, architecture.md.
- 후속 검토: 공개 배포의 실제 브라우저 검증.

## D02 — 내 기기 기록과 전체 랭킹 구분

- 맥락: 사용자 랭킹 서버는 구축 의견 요청이며 신규 DB는 꼭 필요할 경우에만 허용.
- 대안: 즉시 DB 생성 / 가짜 랭킹 / 기기 내 기록과 서버 제안 분리.
- 결정: 현재 게임·학습 기록만 브라우저에 저장, 기록 삭제 제공. 외부 전송·계정·전역 랭킹 없음. 서버 제안은 구현 상태와 분리.
- 이유: Neon은 DB이며 공개 점수 제출을 검증할 API가 별도로 필요. 비용·보존·위변조 검증을 먼저 정해야 함.
- 영향: core.js, app.js, README.md.
- 후속 검토: 서버 권위 재현/런 티켓/속도 제한과 무료 한도 확정 후 연결.

## D03 — 재현 가능한 도전 코드

- 맥락: 반복 플레이는 무작위, 친구와 같은 문제·판 비교는 동일 조건 필요.
- 대안: Math.random만 사용 / 모든 판 고정 / seed 기반 생성.
- 결정: 새 판은 crypto 기반 seed; 같은 버전·설정·seed면 같은 초기 조건. 입력은 길이·문자 제한. 게임별 규칙 검증과 생성 시험.
- 영향: model, core, app, tests.
- 후속 검토: 클라이언트 점수는 전체 랭킹 증거로 신뢰하지 않음.

## D04 — 규칙과 작업 화면

- 맥락: 시각적인 소개보다 실제 학습·플레이 완주가 중심인 서비스 요청.
- 대안: 공통 카드형 소개 사이트 / 프로젝트별 직접 조작 화면.
- 결정: 56개 범주·단계 조합의 템플릿 생성 방식을 선택했습니다. 임의 AI 호출보다 정답·풀이의 일관성과 재현성이 중요하기 때문입니다. 오답 조건을 저장하고 복습 성공 때 제거하며, 개념 템플릿 반복을 무한한 서로 다른 문항으로 홍보하지 않습니다.
- 이유: 학습과 플레이 결과를 재현하고 확인할 수 있게 함.
- 영향: dist/src/, dist/index.html, dist/styles.css, test/, README.md.
- 후속 검토: 공개 URL에서 조작과 작은 화면 검증. 기록 보존 범위 변경은 별도 결정 기록 필요.

## D05 — 은행 v2와 v1 오답 보존 (2026-10-09, LOCAL ONLY)

- 맥락: 문제 수준을 바꾸면서 저장된 seed의 의미와 과거 XP·오답을 유지해야 함.
- 대안: 기존 생성기 직접 교체 / 모든 기록 삭제·초기화 / 버전 라우터와 고정 v1 생성기.
- 결정: questions.js의 v1 생성 로직과 RNG 호출 순서를 그대로 유지. 신규 bank.js에서 v2를 기본으로 제공하고 버전 없는 오답은 v1로 복원. 저장 키 유지, 새 오답에는 버전과 출제 범주 저장. 정답 복습은 버전까지 일치한 항목만 제거. 알 수 없는 레코드는 보존하고 복습에서만 제외.
- 보존 결정: 기존 200개 자동 FIFO 삭제를 중단. 200개 이상일 때 신규 오답만 추가하지 않고 안내. 기존 200개 초과 기록도 로드 시 자르지 않음. 수동 기록 삭제와 정답 복습 제거는 기존 기능 유지.
- 이유: 무관한 과거 기록 손실 없이 조건을 재현. 공개 미래 버전도 과거 seed 의미를 바꾸지 않는 방식으로 추가해야 함.
- 영향: bank.js, app.js, questions.js(고정 의도 주석만), test/bank.test.js, README.md.
- 후속 검토: 주 담당자의 실제 브라우저 기존 기록 마이그레이션 QA. 잘못된 데이터가 있는 기록의 별도 복구 UI는 구현하지 않음; JSON 내보내기로 보존.

## D06 — 추론군·단계·도전 시간

- 맥락: 기존 단일 산술·개념 확인을 수학/전공 다단계 문제로 확대하고 3분 제한을 조정.
- 대안: 큰 숫자로만 난도 증가 / 모든 문항을 수능 기출로 표현 / 자체 제작과 허가된 번안을 구분한 추론군.
- 결정: 16개 범주 × 3개의 서로 다른 추론군 = 48개. 1/2단계는 기본 추론 안내/독립 수행, 3/4단계는 복합 조건 안내/독립 수행. 주사위 패턴·조건 변화는 별도 군으로 중복 계산하지 않음. 혼합 범주는 24개 군을 seed 순열로 순환.
- 시간 결정: 10문제에 20/25/30/40분. 실제 표준 시험 시간이 아닌 연습용 정책. 정답·해설은 종료 후 10문제 전체에서 확인; 미제출을 자동 오답 저장하거나 XP 지급하지 않음. 타이머 콜백뿐 아니라 답 제출 시각도 검사.
- 이유: 조건을 식으로 바꾸고 검산할 시간 확보. 1/2, 3/4가 완전히 다른 네 수학적 난도라고 주장하지 않음.
- 영향: math-bank.js, cs-bank.js, bank.js, app.js, index.html, styles.css, README.md.
- 후속 검토: 인간 학습자 난이도·시간 타당도 검증 NOT_RUN. 그래프형 새 v2 문항은 식/좌표 설명으로 제공하며 v1 그래프 조작을 보존.

## D07 — 출처·라이선스 분리

- 맥락: 사용자가 비상업적 번안을 허용한 MIT OCW 시험 일부의 원문·해설을 주 담당 Codex 에이전트가 조사하고 구현 세션에 근거를 제공.
- 대안: 전부 자체 제작 / 원문 전체 복제 / 필요한 7개 군만 번안.
- 결정: 41개 자체 제작군, 7개 번안군. 매 문항과 저장소 문서에 원저자, 시험, 번호, 원문·해설, CC BY-NC-SA 4.0 및 구체적 변경 고지. 번안 콘텐츠와 그 풀이에 같은 라이선스 적용. 무관한 실행 코드와 자체 제작 콘텐츠 전체에 재허가 고지를 확장하지 않음. MIT 로고·제휴·보증 표현 없음.
- 이유: 출처 투명성과 권리 범위 보존. 실제 수능 기출이라는 근거 없는 주장을 방지.
- 영향: sources.js, math-bank.js, cs-bank.js, content-license.html, app.js, docs/content-bank.md.
- 후속 검토: 비상업적 콘텐츠 정책을 바꾸거나 상업적 배포를 하려면 별도 권리 검토 필요. 이번 작업은 로컬 수정이며 commit/push/deploy 없음.

## D08 — 검증 근거 분리

- 맥락: 생성기 공식을 그대로 복제한 시험만으로 문항 정답을 보증할 수 없음.
- 대안: 자기 정답 재제출만 확인 / 모든 검증을 실제 브라우저에 의존 / 독립 오라클과 UI QA 분리.
- 결정: 48개 군 전체에 별도 오라클. 주사위·정수해·그래프 후보를 열거, 카드 순열·버튼 경계 검증, 코드 문장을 Node VM에서 실행, SQL은 메모리 SQLite 실행, 최적화·적분은 수치 검산. v1 2,240개 출력의 기존 SHA-256 고정. DOM 테스트 더블은 별도 표시하고 실제 브라우저로 표현하지 않음.
- 이유: 정답 로직과 별도 접근으로 수치·조건 오류를 찾고, 렌더링·사용성·표준 난이도는 별도 검증으로 남김.
- 영향: test/bank.test.js, docs/verification-v2.md.
- 후속 검토: 주 담당자 브라우저 smoke 및 인간 문항 검토. SQLite는 SQL 표준 예제 범위의 교차 검증이며 PostgreSQL 연결 증거가 아님.

## D09 — 첫 화면은 복합 조건 독립 풀이 (2026-10-09, LOCAL ONLY)

- 맥락: 주 담당 Codex 에이전트의 실제 브라우저 확인에서 첫 무작위 문항이 1단계 moving-bound의 직접 대입 문제였음. 사용자는 이전 문항이 너무 쉬웠으며 첫 경험부터 수능형·대학 전공형 추론을 원함.
- 대안: 1단계 기본 유지 / 4단계 기본으로 전환 / 이번 후속에서 문제은행 전체를 다시 설계.
- 결정: 페이지 로드 시 수학 혼합·4단계 복합 조건 독립 풀이를 기본으로 선택. HTML selected, JS 초기값, 세션 시작 시 선택 메뉴, 초기 문구를 일치시킴. 1~3단계는 자유롭게 선택 가능. 낮은 단계 smoke는 테스트·인계 문서에서 단계를 명시적으로 선택.
- 이유: 첫 화면부터 사용자가 요청한 복합 추론 경험을 제공. 4단계라는 표시는 제공 조건·안내 유무를 뜻하며 공인 시험 수준 인증으로 해석하지 않음.
- 영향: dist/index.html, dist/src/app.js, test/app.test.js, README.md, docs/verification-v2.md. docs/content-bank.md와 D07의 근거 제공 주체도 주 담당 Codex 에이전트로 정정.
- 후속 검토: 주 담당 Codex 에이전트가 첫 화면·1/4단계 smoke를 실제 브라우저에서 확인. 이 후속 구현 세션은 DOM 테스트 더블과 로컬 검사만 수행하며 새 원문 조사·라이브 검증은 수행하지 않음.
