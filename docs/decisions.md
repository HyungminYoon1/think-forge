## D05 — 은행 v2와 v1 오답 보존 (2026-10-09, LOCAL ONLY)

- 맥락: 문제 수준을 바꾸면서 저장된 seed의 의미와 과거 XP·오답을 유지해야 함.
- 대안: 기존 생성기 직접 교체 / 모든 기록 삭제·초기화 / 버전 라우터와 고정 v1 생성기.
- 결정: questions.js의 v1 생성 로직과 RNG 호출 순서를 그대로 유지. 신규 bank.js에서 v2를 기본으로 제공하고 버전 없는 오답은 v1로 복원. 저장 키 유지, 새 오답에는 버전과 출제 범주 저장. 정답 복습은 버전까지 일치한 항목만 제거. 알 수 없는 레코드는 보존하고 복습에서만 제외.
- 보존 결정: 기존 200개 자동 FIFO 삭제를 중단. 200개 이상일 때 신규 오답만 추가하지 않고 안내. 기존 200개 초과 기록도 로드 시 자르지 않음. 수동 기록 삭제와 정답 복습 제거는 기존 기능 유지.
- 이유: 무관한 과거 기록 손실 없이 조건을 재현. 공개 미래 버전도 과거 seed 의미를 바꾸지 않는 방식으로 추가해야 함.
- 영향: bank.js, app.js, questions.js(고정 의도 주석만), test/bank.test.js, README.md.
- 후속 검토: 주 담당자의 실제 브라우저 기존 기록 마이그레이션 QA. 잘못된 데이터가 있는 기록의 별도 복구 UI는 구현하지 않음; JSON 내보내기로 보존.

## D06 — 추론군·단계·도전 시간

- 맥락: 기존 단일 산술·개념 확인을 수학/전공 다단계 문제로 확대하고 3분 제한을 조정.
- 대안: 큰 숫자로만 난도 증가 / 모든 문항을 수능 기출로 표현 / 자체 제작과 허가된 번안을 구분한 추론군.
- 결정: 16개 범주 × 3개의 서로 다른 추론군 = 48개. 1/2단계는 기본 추론 안내/독립 수행, 3/4단계는 복합 조건 안내/독립 수행. 주사위 패턴·조건 변화는 별도 군으로 중복 계산하지 않음. 혼합 범주는 24개 군을 seed 순열로 순환.
- 시간 결정: 10문제에 20/25/30/40분. 실제 표준 시험 시간이 아닌 연습용 정책. 정답·해설은 종료 후 10문제 전체에서 확인; 미제출을 자동 오답 저장하거나 XP 지급하지 않음. 타이머 콜백뿐 아니라 답 제출 시각도 검사.
- 이유: 조건을 식으로 바꾸고 검산할 시간 확보. 1/2, 3/4가 완전히 다른 네 수학적 난도라고 주장하지 않음.
- 영향: math-bank.js, cs-bank.js, bank.js, app.js, index.html, styles.css, README.md.
- 후속 검토: 인간 학습자 난이도·시간 타당도 검증 NOT_RUN. 그래프형 새 v2 문항은 식/좌표 설명으로 제공하며 v1 그래프 조작을 보존.

- 결정: 페이지 로드 시 수학 혼합·4단계 복합 조건 독립 풀이를 기본으로 선택. HTML selected, JS 초기값, 세션 시작 시 선택 메뉴, 초기 문구를 일치시킴. 1~3단계는 자유롭게 선택 가능. 낮은 단계 smoke는 테스트·인계 문서에서 단계를 명시적으로 선택.
- 이유: 첫 화면부터 사용자가 요청한 복합 추론 경험을 제공. 4단계라는 표시는 제공 조건·안내 유무를 뜻하며 공인 시험 수준 인증으로 해석하지 않음.

## D10 — 수치 중간값의 선택형 풀이 점검 (2026-10-09, LOCAL)

- 맥락: 수학·전공의 실제 다단계 과제에 정의된 기준에 따른 풀이 입력을 추가하도록 승인받음. 정답과 풀이 점검을 구분해야 함.
- 대안: AI/서버 자유 서술 채점 / 키워드 존재 검사 / 수치 중간값을 각각 독립 점검.
- 결정: composition, triangle-section, bayes, projection, poster-optimum, cpu-scheduling, packet-pipeline, dag-critical-path의 8개 군. 각 라벨의 수치 중간값에 1점, 동치 분수·소수 인정, 빈 값은 미작성, 잘못된 값은 0점. 전체 증명·자유 서술 이해도를 채점한다고 표현하지 않음. 기존 최종 답과 XP는 별개.
- 저장 결정: 입력 최대 40자씩, 2~3개 필드. 입력·점검 결과는 세션 메모리에만, 영속 저장·내보내기 제외. 학습은 제출 후, 시험은 종료 후 기준값/부분 점수를 표시.
- 이유: 기준을 사용자가 읽고 검산할 수 있으며 외부 전송 없이 결정적으로 평가. 7개 번안군의 기존 출처·권리 범위 유지; 번안군의 수치 풀이 점검도 해당 파생 풀이에 포함.
- 영향: reasoning.js, app.js, index.html, styles.css, test/reasoning.test.js, test/app.test.js, README.md, architecture.md.
- 후속 검토: 주 담당자의 실제 브라우저 폼·키보드·시험 종료 피드백 캡처. 인간의 풀이 타당성/문항 난이도 평가 NOT_RUN.

## D11 — 실제 독립 완료 증거의 제한된 기기 저장

- 맥락: 기기별 갤러리 완료 배지는 방문·힌트가 아닌 실제 독립 성취에서 재계산해야 하며 제한된 로컬 저장 추가가 승인됨.
- 대안: 기존 correct/XP를 완료로 환산 / seed만 중복 방지 / 문제군 성취와 실제 조건의 공개·시도 이력 저장.
- 결정: achievements.version=1, allowlist의 48개 family만 성취로 보관. 2·4단계, 첫 시도 정답, 힌트·풀이 기준 미사용, 오답 복습 아님일 때만 문제군을 1회 추가. 조건의 family+기본/복합 구분+params를 저장하여 seed/index 변경 및 1→2/3→4 전환만으로 같은 풀이를 독립 완료로 승격하지 않음.
- 보존 결정: 조건 문자열 최대 1,024자, 최대 1,000개, FIFO 삭제 없음. 한도 이후 새 완료 판정 중단, 기존 완료 보존. 조건 판정은 로컬 학습 보조 기록이며 위변조 방지 인증 아님. XP 1e9 상한을 제출 시에도 적용. 오답 200개 정책·기존 초과/알 수 없는 오답·v1 생성·JSON 내보내기 유지.
- 공개 결정: 힌트·풀이 기준을 실제 열거나 답 제출·건너뜀 때 조건을 기록. 시험 종료 후 미제출 해설을 실제 펼칠 때에도 기록하지만 XP/오답/제출 횟수는 추가하지 않음. 초기 뷰와 닫힌 종료 복습은 성취나 시도로 기록하지 않음.
- 이유: 정답을 본 같은 조건을 새 코드나 단계로 재제출해 완료 수를 늘리는 경로 차단. 실제 사용자 답·풀이 텍스트·날짜 없이 제한된 증거만 저장.
- 영향: achievements.js, app.js, index.html, test/progress.test.js, test/app.test.js, README.md, architecture.md.
- 후속 검토: 브라우저 재로드·공개 해설·저장 차단·삭제 QA는 주 담당자. 한도 변경이나 이력 순환은 별도 결정 필요.

- 오류·삭제 결정: 파싱/형식/한도/저장 오류는 원본 요약을 덮어쓰지 않고 실패. 개인 기록 삭제 성공 후 자기 항목만 제거, 형제 항목 보존. 일부 삭제 실패는 화면에 표시.
- 이유: 갤러리에서 배지를 읽는 데 필요한 최소 정보만 제공. 이름·seed·행동·파일·입력 원문 없음; 네트워크·랭킹 없음.
