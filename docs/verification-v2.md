## 실제 브라우저 smoke — 주 담당자 실행 필요 (NOT_RUN)

`npm run dev -- 0`의 loopback URL을 주 담당자 preview에서 열어 아래 흐름을 확인합니다. 이 세션은 브라우저 도구를 사용하지 않았습니다.

1. 새 페이지를 열면 수학 전체 혼합·**4단계 복합 조건 독립 풀이**가 선택되어야 합니다. 선택 메뉴와 문제 경로 모두 4단계인지, 자동 삽입된 풀이 출발점이 없는지 확인합니다. 그다음 **1단계를 명시적으로 선택**하고 도전 코드 `smoke` 적용. 첫 문항은 **도함수 부호와 극값**, 정답 `108`. 빈 답은 진행/기록을 바꾸지 않아야 합니다. `108` 제출 후 풀이, 다음 문제, `8`(내분 넓이), 다음 `81`(수열 복원)을 확인합니다.
2. 수학 → 확률 → 4단계 → `smoke`. 순서와 정답: `dice-pattern` **36/125**, `adjacent-expectation` **24/11**, `bayes` **400/499**. `72/250`도 첫 정답과 동치입니다. 각 출처 패널에 저자·Problem 번호·원문/해설/라이선스 링크·변경 고지 확인. 링크는 별도 탭.
3. 수학 → 미적분·최적화 → 4단계 → `smoke`. **포스터 최적화 1296**, 다음 **적분 상한 510**, 다음 **넓이 17/2**. 자체 제작/번안 표시 차이 확인.
4. 컴퓨터과학 → 전공 전체 혼합 → 4단계 → `smoke`. 첫 세 문항: **클로저 20**, **배낭 12**, **GROUP BY 2**. SQL 표의 NULL과 줄바꿈, 긴 코드의 모바일 폭을 확인합니다.
5. 컴퓨터과학 → 데이터베이스·SQL → 4단계 → 10문제 도전 → `smoke`. 타이머 **40:00** 근처, 추가 힌트 버튼 비활성. 10번 건너뛰기/다음 문제로 끝까지 진행. 결과에 10개 접이식 복습, 내 답·정답·해설·출처, SQL 표 확인. 첫 세 정답은 **3, 1, 2**. 한 문항 두 번 제출 시 건수/XP가 중복 증가하면 안 됩니다.
6. 위 오답 복습을 열어 같은 조건·버전·seed가 재현되는지 확인하고 정답을 맞힌 해당 항목만 제거되는지 확인. 기존 실제 기록에서 버전 없는 오답이 있으면 v1 표시와 예전 문항 유지 확인. **실제 사용자의 저장소를 테스트용으로 덮어쓰지 마세요.** 필요하면 별도 QA 브라우저 프로필 사용.
7. JSON 내보내기에서 상위 `version:2`, `currentBankVersion:2`, 새 오답 `bankVersion:2`와 기존 기록 보존 확인. 로컬 저장 차단 상태에서는 저장 오류 안내와 학습 지속 여부 확인.
8. 390×844와 320×720에서 긴 문항·분수 입력(슬래시 입력 가능)·출처·표·종료 복습의 가로 넘침, 키보드 탭/Enter, 정답/오답 상태 읽기를 확인. 기존 v1 그래프 오답에서는 클릭/키보드 점 선택도 확인.
9. 시간 만료는 별도 QA 시계 제어가 가능하면 4단계 도전을 40분 이후로 진행해 확인. 만료 후 답은 점수에 더해지지 않고 10개 전체 복습에 미제출 표시. 이 세션은 동일 경계를 DOM 더블로 검증했고 실제 시간 대기/브라우저 타이머는 NOT_RUN.
10. 하단 문항 출처·라이선스 페이지가 열리고 앱으로 돌아오는지 확인. DevTools에서 예상치 못한 런타임 요청 및 콘솔 오류가 없는지 확인. CSP `connect-src 'none'` 유지.
